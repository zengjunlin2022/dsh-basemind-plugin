basemind is this repository's indexed context layer: a tree-sitter code map, git history at symbol resolution, document search and shared memory. Its tools are always loaded; call them directly, before shell `rg`/`grep`/`find`/`git` and before reading whole files. They return paths, 1-based line numbers and signatures, so they cost a fraction of the tokens of reading source.
Code:
- what is in a file: code_outline {"path":"src/store.rs"}, then code_read {"path":"src/store.rs","symbol":"open"} for only the body you need
- where is X defined: code_symbols {"name":"open_store"}
- what calls / implements / imports X: code_refs {"name":"open_store"}
- find a string or comment in code, markdown, config and data files: code_grep {"pattern":"cache_root("} (literal unless "regex":true)
- find code by what it does: code_search {"query":"retry a failed upload"}
- find a file by name: find_files {"query":"readme"}
History: git_log {} (recent commits; add path, query, author, symbol or rev), git_blame {"path":"src/store.rs","symbol":"open"}, git_diff {} (working-tree status; add path, from, to).
Documents by meaning (PDFs, Office, markdown, notebooks): docs_search {"query":"how releases are versioned"}.
Memory shared across sessions: memory_save {"key":"decision/x","value":"…"}, memory_search {"query":"…"}.
Index: it follows your edits. index_status {} when a result is unexpectedly empty; when a result says stale or a new file is missing, index_rescan {"paths":["src/store.rs"]} for the files you touched; index_rescan {} only when index_status reports an empty index, degraded or rescan_needed.
Conventions: paths are repository-relative with forward slashes; line and end_line are 1-based and inclusive; lists take limit and cursor, and next_cursor alone says a list goes on (a limit cut is paging, not truncation); a list trimmed to its token budget also sets budgeted; a cut the caller did not ask for sets truncated and truncated_reason, with omitted counting the items left out where known (follow next_cursor if there is one, else narrow the call); a failure is a tool result with isError naming the fix and structuredContent {error, retryable}, error being invalid_argument, unavailable, index_unavailable, busy, cancelled or internal; a notice field means the result is incomplete and says why. An unknown argument is rejected, never ignored.
The agent tools agent_post, agent_inbox and agent_threads are listed separately; they are needed only when collaborating with other agents in this repository. They carry threads of messages; reading marks read, and a subagent passes `as` to keep its own inbox.
