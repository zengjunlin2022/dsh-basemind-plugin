## 3. Critical (Must Fix)

### C1. `package.json` 0.2.0 沒有進 staged index，`v0.2.0` release 必然失敗

- **位置：** [package.json](../package.json#L3)、[release.yml](../.github/workflows/release.yml#L52-L57)
- **已確認事實：**
  - `git show :package.json` → `"version": "0.1.6"`；`git show HEAD:package.json` 也是 `0.1.6`；worktree 是 `0.2.0`。
  - `git diff --cached --stat` 只有 17 files，不含 `package.json`；`git diff --cached -- package.json` 為空。
  - Git stat cache 遮蔽了它：worktree blob `06f7642…` vs index blob `b3cddcf…`，但 size 與 mtime 相同，`git status`/`git diff` 不報。`git hash-object --path=package.json` 與 `git show :package.json` 才看得到差異。
  - 其餘 17 個 staged 路徑的 worktree 內容與 index blob 相同（本審查另行核對），所以測試結果對應 staged 內容，但 version bump 不在其中。
- **影響：**
  - 以目前 index commit 後推 `v0.2.0`，release workflow 的 `Verify the tag matches package.json` 會得到 `0.2.0`（tag）vs `0.1.6`（package），執行 `::error::tag v0.2.0 does not match package.json version 0.1.6` 並 `exit 1`。
  - 本地 `npm run check` / `npm pack` 讀 worktree，會顯示 0.2.0 並產生 `dsh-basemind-plugin-0.2.0.tgz`，因此本地驗證**不會**暴露這個落差。
  - CHANGELOG 已宣告 `## [0.2.0]`、Execution Report §1/§2 也宣稱 `package.json` 已改 0.2.0，文件與 staged tree 矛盾。
- **最小修法（由使用者執行）：**
  1. `git add package.json`
  2. `git diff --cached -- package.json` 應只見 `-0.1.6/+0.2.0`
  3. `git diff --cached --stat` 應變成 18 files
  - 不需要修改程式碼。

## 4. Important (Should Fix)

### I1. `compat.yml` 的 macOS job 無法執行，無法產生它宣稱的 macOS 證據

- **位置：** [compat.yml](../.github/workflows/compat.yml#L26-L27)、[compat.yml](../.github/workflows/compat.yml#L49)
- **三個獨立的失敗原因：**
  1. **Runner label 已退役：** `macos-14` 自 **2026-11-02** 起從 GitHub Actions 退役（[actions/runner-images README](https://github.com/actions/runner-images/blob/main/README.md)），目前 2026-11-24 已不可用。
  2. **架構不符：** `macos-14` 是 **x64** runner；workflow 下載的是 `basemind-aarch64-apple-darwin.tar.gz`（arm64）。BaseMind 0.34.0 release 沒有 macOS x86_64 asset（官方 assets 只有 `basemind-aarch64-apple-darwin.tar.gz`）。即使 label 可用，binary 也無法執行。
  3. **`sha256sum` 在 macOS 不存在：** macOS 預設只有 `shasum`（Perl）；`compat.yml:49` 直接呼叫 `sha256sum -c -`，會在 checksum 步驟 `command not found` / exit 127。`release.yml` 在 ubuntu 使用不受影響。
- **影響：** 這個 workflow 是本次交付唯一的 macOS 相容性證據；三個 fail-fast 之前就會失敗，無法驗證 initialize / tools-list / `index_status` / `code_outline`。這不是 release workflow（ubuntu）的阻擋項，但 macOS 測試計畫實際未落地。
- **最小修法：**
  - macOS row 改用目前 arm64 label，例如 `macos-15`（arm64）或 `macos-latest`（README 顯示目前為 macOS 26 arm64），並保留 `basemind-aarch64-apple-darwin.tar.gz`。
  - checksum 改為跨平台分流：`command -v sha256sum >/dev/null 2>&1 && sha256sum -c - || shasum -a 256 -c -`（或 Ubuntu/Windows 用 `sha256sum`、macOS 用 `shasum -a 256`）。
  - 修正後手動 dispatch 一次 workflow；目前它從未實跑。

### I2. CHANGELOG 0.2.0 的 Fixed 條目描述了實作不存在的 `index_rescan {}`

- **位置：** [CHANGELOG.md](../CHANGELOG.md#L27)、[integration.test.mjs](../test/integration.test.mjs#L557-L577)
- **已確認事實：**
  - CHANGELOG:27 寫「It warms the index with `index_rescan {}` before the read tools run」。
  - 實際 `ensureIndexed()` 只輪詢 `index_status`；同檔註解明寫「it must not call `index_rescan {}`, which blocks far longer than any sane tool timeout」。
  - Execution Report §4.2 也把它列為 deviation 2；[AGENTS.md](../AGENTS.md#L109) 更以粗體規定 integration「**不呼叫 `index_rescan {}`**」。
- **影響：** Release notes 與專案規則直接衝突；日後維護者照 CHANGELOG 還原 rescan 會立即踩冷索引 timeout。
- **最小修法：** 改成「polls `index_status` until `indexing` clears, because `index_rescan {}` exceeds the tool timeout on a cold cache」。

### I3. 舊版相容的可執行證據不足，AGENTS/CHANGELOG 措辭超出實際覆蓋

- **位置：** [compat.yml](../.github/workflows/compat.yml#L20-L34)、[integration-legacy.test.mjs](../test/integration-legacy.test.mjs#L320-L323)、[AGENTS.md](../AGENTS.md#L108)、[CHANGELOG.md](../CHANGELOG.md#L15)
- **已確認事實：**
  - compat matrix 三個 row 全部下載 **0.34.0**，沒有 0.33/0.32 row。
  - `integration-legacy.test.mjs` 在 0.34 上只會走 `index_status` 分支；`admin { mode: 'status' }` fallback 在任何 CI/本機驗證中都不會被執行，`payload()` 對 `admin status` 文字是 JSON 的假設也未被驗證。
  - AGENTS 寫「用 `BASEMIND_BIN` 跑舊版（0.29.3–0.33.0）回歸 smoke」，CHANGELOG 寫「version-agnostic smoke test for older binaries」，讀者會以為舊版已被覆蓋。
  - Execution Report §5 已誠實列出 0.33/0.32 未驗證，所以不是隱瞞，但對外措辭仍超出證據。
- **影響：** 本次交付宣稱 0.29.3–0.34.0 同一份程式碼可服務；目前只有 0.29.3 fixture（schema 層）+ 一份只跑 0.34 的 smoke。舊版真正的 handshake / tool discovery / `admin` 路徑沒有被執行。
- **最小修法（二選一）：**
  - 在 compat matrix 增加一個 `basemind 0.33.0` row（或 `workflow_dispatch` input `basemind_version`），只跑 `integration-legacy.test.mjs`；或
  - 把 AGENTS/CHANGELOG 改成「可對舊版執行；目前 CI 僅以 0.34.0 驗證 smoke 本身，0.33/0.32 未實跑」。

## 6. Strengths

- **Runtime 改動最小且安全：** 只改 [lib/tool-bridge.js](../lib/tool-bridge.js)；`index.js`、`schema.js`、`mcp-session.js`、`stdio-client.js`、`result.js`、`workspace-pool.js`、`config.js` 無 staged 變更。Legacy 成功結果 key 只有 `content,isError,text`，不會出現 `structuredContent: undefined`；`error:''`、`error:5`、`structuredContent:null`、非 Error throw、`code:'ENOENT'` 等邊界都安全，仍 throw `Error`。
- **假通過通道真的關掉：** `BASEMIND_REQUIRE_INTEGRATION=1` + 無 binary → exit 1 / 8 failed；無旗標 + 無 binary → exit 0 / 8 skipped；`BASEMIND_BIN` 無效 → `before()` fail。實測吻合。
- **契約固定方式可驗證：** staged fixture 是 18 工具真實採集，15 個 `_meta["anthropic/alwaysLoad"]`、無 `outputSchema`、無 `mode` property；instructions fixture 與 0.29.3 不同；properties/required/enum 比對有實際對象。
- **真實 0.34.0 契約一致：** `serverInfo` rmcp 3.11.0、protocol 2025-06-18、資源只有 status + outline/memory templates；README/CHANGELOG 的 15+3、resources、repository group 敘述與實測一致。
- **隔離可靠：** 兩個 integration 檔都在 module load 強制覆寫 `BASEMIND_DATA_HOME` / `BASEMIND_COMMS_DIR`，cleanup 會停自己的 daemon；不碰使用者預設 cache。
- **Execution Report 誠實：** Phase 4 部分完成、Phase 5 未執行、CI 未實跑、macOS/舊版 binary 未驗證都明列。
